# 非暴力沟通改写 Skill — 设计规格

日期：2026-11-02  
状态：草稿待审  
形态：轻量改写器（单 skill，内部分场景换语气）

## 1. 目标

把用户「原本想说的话」改写成更友好、更适合沟通的话语，**不改变本意**。  
核心公式（钉死）：**事实 + 感受 + 需要 + 请求**（与 Marshall Rosenberg 非暴力沟通四要素一致；用户口语称「观察」处统一为「事实」亦可，输出说明标题用：观察/感受/需要/请求）。

不做：代发消息、心理咨询、关系诊断、「该不该说」的决策、把批评扩成谈判方案。

## 2. 触发

- 自然语言：非暴力沟通 / NVC / 把话说软一点 / 改友好一点 / 贴了要改写的原话  
- 备选口令：`/非暴力沟通`  
- 语言跟随输入（中文进中文出）

## 3. 流程

1. **读原话** → 按语意判定主场景：工作 / 私聊 / 邮件（交叉取主场景，如「给老板的微信」→ 工作）  
2. **信息缺口**：缺对方是谁、或缺「要对方做什么」等关键信息 → **只短问一句**，答完再改；用户说「别问了就改」→ 按字面改，并在说明中标假设  
3. **输出两块**（固定格式）：

```
【改写】
（可直接发出的全文；语气随场景）

【说明】
观察：…   # 可核对的事实（不做评价）
感受：…   # 情绪词，不指责对方人格
需要：…   # 说话者在意什么
请求：…   # 具体、可答应或拒绝的一句
```

说明四行只解释改写依据，**不另开一套新要求**。

## 4. 场景语气

| 场景 | 对象感 | 语气要点 |
|------|--------|----------|
| 工作 | 同事/合作方/上级 | 清楚、尊重、可执行；少情绪堆砌 |
| 私聊 | 家人/朋友/伴侣 | 更近人、可带感受；不指责、不贴标签 |
| 邮件 | 正式长文 | 称呼/事由/请求/收尾完整；礼貌但不空套话 |

说明里标一句「按××场景改写」。

## 5. 硬规则

- **不改本意**：不软化成另一套诉求，不扩 scope  
- **不编造**：原话没有的事实、情绪、请求不得写入改写正文；推断仅可出现在「假设」标注或短问  
- **不代发**：只交可复制文本  
- **稳定优先于花哨**：短消息保持短；邮件才拉长结构

## 6. 参考案例（用户提供）

爷爷微信（私聊）：「这一阵子都未主动要我发点钱了我很焦虑不知可有另钱花了告知」

- 观察/事实：这一阵子你没有主动跟我要钱  
- 感受：我很焦虑  
- 需要：想确认你手头是否够用 / 仍需要我支持  
- 请求：告诉我一声有没有另钱花  

社区概括模板：**事实 + 感受 + 需要和请求**。本 skill 的【说明】四行与此对齐；【改写】应保留这份温暖与本意，不改成说教。

## 7. 成功标准

- 改写可直接发出  
- 本意与原话一致（人工对照）  
- 【说明】四行齐全且与改写对应  
- 场景风格匹配  
- 缺信息时先短问，不瞎猜硬改（除非用户明确跳过）

## 8. 非目标（首版不做）

- 多语言对照表、脚本硬门禁（可二期借鉴 oral-to-prompt）  
- 公开 GitHub 仓 / README 专家流程（用户另说再开）  
- 自动走 send-on-behalf 代发

## 9. 实现落点（获批后）

- 经 `UpdateSkill` 写入用户 skill 库；测试用贴案例冒烟
